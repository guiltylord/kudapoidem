# «КудаПойдем» (VibeMatch) — Mobile-First MVP

> **Telegram Mini App для мгновенного выбора мест отдыха с друзьями на основе AI-анализа атмосферы и компромисса вкусов компании.**

Разработано в соответствии с концепцией [`PRODUCT_CONCEPT.md`](./PRODUCT_CONCEPT.md) в формате **First Mobile** (с поддержкой эмуляции мобильного экрана в браузере и адаптивным режимом).

---

## 🚀 Как запустить

### Быстрый старт:
```bash
# Установка зависимостей (уже установлены)
npm install

# Запуск в режиме разработки (Hot Reload)
npm run dev

# Сборка продакшн-бандла
npm run build

# Запуск тестов алгоритма
npm test
```

Сервер разработки будет доступен по адресу: `http://localhost:5173`.

## 📱 Что реализовано в MVP

1. **First Mobile UI & Telegram Mini App Frame**:
   - Интерфейс оптимизирован под смартфон и стилистику Telegram WebApp (темная неоновая тема, карточки с эффектом стекла, микро-анимации, плавные переходы).
   - В браузере доступен переключатель «Смартфон / Широкий экран» — можно тестировать как в рамке смартфона, так и во встроенном эмуляторе DevTools.

2. **Режим создания встречи организатором**:
   - Выбор города: **Москва** или **Санкт-Петербург**.
   - Поле экспресс-настроения: текстовый/голосовой ввод пожеланий своими словами (например: *«хотим уютно поболтать и выпить вина»*) + быстрые чипсы-теги.
   - Банда друзей: гибкое добавление друзей из готовых пресетов (IT, UX, Продакт, Стартапер) или создание новых участников.
   - У каждого участника прямо на лету можно редактировать его **«ДНК досуга»**:
     - Комфортный чек (`₽`, `₽₽`, `₽₽₽`, `₽₽₽₽`)
     - Любимые форматы (Крафт, Вино, Необистро, Спешелти, Паназия, Настолки и др.)
     - Жесткие стоп-факторы и табу (*«Кальяны / Дым»*, *«Орущая музыка»*, *«Теснота»*, *«Дорого»*, *«Веган»*)
     - Настроение на вечер (*«Душевно поболтать»*, *«Погудеть / крафт»*, *«Эстетично при свечах»*).

3. **Алгоритм AI-компромисса (VibeMatch Core Engine)**:
   - Анализирует атмосферу (шумность, освещение, рассадку, музыку, чек).
   - **Жестко отсекает стоп-факторы**: если у участника табу на кальяны — кальянные дисквалифицируются.
   - Считает индекс компромисса: учитывает не только среднее, но и минимальное удовлетворение участников (чтобы ни один друг не скучал).
   - Генерирует блок **«Почему подходит каждому в банде»** с персональным объяснением под каждого участника.

4. **Анимация AI-сканера**:
   - Пошаговый статус: чтение ДНК банды ➔ фильтрация по табу ➔ семантический анализ отзывов Яндекс Карт & 2GIS ➔ расчет Топ-3.

5. **Шорт-лист: Топ-3 места**:
   - Переключение между кандидатами (#1 Чемпион компромисса, #2, #3).
   - Фото, метро, средний чек, вайб-индикаторы (шум, свет, рассадка, музыка).
   - Персональное объяснение соответствия для каждого друга.
   - Выжимка из реальных отзывов об атмосфере.
   - Интерактивное голосование с подсчетом голосов.
   - Кнопка «Утвердить выбор банды».

6. **Виральная шеринг-карточка (Growth Loop)**:
   - Итоговая карточка выбранного места.
   - Кнопка **«Скопировать карточку в Telegram чат»** (форматирует стильное Markdown-сообщение с эмодзи, адресом и обоснованием для вставки в групповой чат).
   - Прямой переход к маршруту на Яндекс Картах и кнопка звонка.

7. **Таб «ДНК досуга»**:
   - Управление личным профилем пользователя для мгновенного подтягивания во все встречи.

8. **Таб «Все места»**:
   - Кураторская база культовых мест Москвы и СПб с AI-тегами атмосферы и поиском.

## 🧪 Тестирование

Написан набор автоматических тестов (`src/utils/matcher.test.ts`), покрывающий:
- Расчет компромисса для компании друзей;
- Жесткую дисквалификацию заведений при наличии табу на кальяны;
- Штрафы за шум при табу на громкую музыку;
- Бюджетные ограничения;
- Специфику городов (Москва / СПб);
- Влияние экспресс-промптов;
- Граничные случаи (1 организатор, пустой список участников, сортировка выдачи).

## 🌐 Деплой на GitHub Pages

Проект полностью настроен для автоматического деплоя на **GitHub Pages** через **GitHub Actions**:

1. **Создайте репозиторий на GitHub** (если еще не создан).
2. **Привяжите удаленный репозиторий и запушьте код**:
   ```bash
   git remote add origin https://github.com/<ВАШ_GITHUB_LOGIN>/<ИМЯ_РЕПОЗИТОРИЯ>.git
   git branch -M main
   git push -u origin main
   ```
3. **Включите GitHub Actions для Pages в настройках репозитория**:
   - Перейдите в **Settings** ➔ **Pages** репозитория на GitHub.
   - В разделе **Build and deployment** ➔ **Source** выберите:
     **`GitHub Actions`** (не Deploy from a branch).
4. При каждом пуше в ветку `main` (или `master`) workflow `.github/workflows/deploy.yml` автоматически:
   - Прогоняет тесты (`npm run test`)
   - Собирает бандл (`npm run build`)
   - Разворачивает приложение на GitHub Pages
